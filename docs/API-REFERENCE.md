# API Reference

Every HTTP endpoint in the system, service by service. Generated by reading the
route decorators on the `production` branch and cross-checked against the live
stack's self-documenting `/` endpoints.

## How to call anything

Two equivalent addresses for every sub-app endpoint:

```bash
# through the gateway (what the browser uses)
curl http://localhost:8080/api/<key>/<path>

# direct to the service (debugging only)
curl http://localhost:<host-port>/<path>
```

The gateway forwards method, query string, body, and headers (minus `host` and
`content-length`) with a **15-second timeout**. An unreachable upstream returns
`502` with `{"error": "<Name> unavailable", "detail": "..."}`. An unknown app
key returns `404` with `{"error": "unknown app '<key>'"}`.

**Universal endpoints.** Every service implements two:

| Endpoint | Returns |
|---|---|
| `GET /` | `{"app": "<Name>", "endpoints": [...]}` — self-documentation |
| `GET /health` | liveness; the gateway's fan-out probe depends on this |

They are omitted from the per-service tables below.

## Gateway — `:8080`

The only browser-facing service.

| Method | Path | Description |
|---|---|---|
| `GET` | `/api/apps` | The sub-app catalog the dashboard renders from: `key`, `name`, `description`, `icon` for each registered service. Order matters — it is the card order on the homepage. |
| `GET` | `/api/health` | Probes every registered service's `/health` **concurrently** with a 3s timeout each. Returns `{<key>: {"key", "status": "up"\|"down", "detail"}}`. A down service reports the exception text as `detail` rather than failing the whole response. |
| `*` | `/api/{app_key}/{path:path}` | Reverse proxy. Methods: `GET`, `POST`, `PUT`, `PATCH`, `DELETE`. |
| `GET` | `/*` | Static SPA from `gateway/static/`, served with `Cache-Control: no-cache`. |

## assistant — `:8085` — the home screen, and the calendar sync

Reads the services the home screen needs and composes one payload. The only
service that writes across app boundaries (into `schedule`).

| Method | Path | Description |
|---|---|---|
| `GET` | `/home?fresh=0` | The composed homepage payload: `week`, `money`, `budget`, `portfolio`, `resale`, `amex`, `weather`, `deploy`, `data_safety`, `import_run`, `disk`. `fresh=1` forces a re-read of upstream sub-apps instead of serving the cached composition. |
| `POST` | `/sync` | Reads gmail's triage, books interviews the mail names a time for, diffs availability threads against `thread_state`, pulls Google Calendar, retires stale holds. Runs on a timer via `AUTO_SYNC_SECONDS`; the route is the manual trigger. Idempotent — an unchanged thread is a no-op. |
| `POST` | `/notify?text=` | Send yourself `text` on the configured channel now. |

`AUTO_SYNC_SECONDS` makes `/sync` run on a timer; `0` (the default) means
manual only. `NOTIFY_ON_SYNC=true` texts the sync's notable changes after each
run. The `/briefing`, `/ask` and Telegram question-answering routes were
removed on 2026-10-06 with the services they read.

## core — `:8098` — the settings store

One JSONB row. Holds `market.holdings` / `market.watchlist` (read by
`stocks`), `budgets` and `paycheck` (read by `budget`), `weather` (read by
`weather`) and `finance.not_spendable` (read by the assistant's runway). The
⚙ modal on the home screen is what writes it. The habit-tracking and
daily-score endpoints this service used to carry were removed on 2026-10-06.

| Method | Path | Description |
|---|---|---|
| `GET` | `/settings` | The settings blob. |
| `PUT` | `/settings` | Patch settings. Body is a partial dict, shallow-merged in. |

## gmail — `:8083` — inbox triage and availability detection

Holds its own Google OAuth. **Polls in the background every 6 hours**; all read
endpoints serve the last completed sync, so a page load costs no Gmail API
calls.

| Method | Path | Description |
|---|---|---|
| `GET` | `/needs-reply` | Inbox triage — what actually needs a reply, with deadlines flagged. |
| `GET` | `/thread-availability` | Scans **sent** mail for your own "I'm available X at Y" proposals and tracks whether the other side confirmed, countered, or declined. This is the input to the calendar pipeline. |
| `GET` | `/summary` | Rolled-up counts for the dashboard card. |
| `GET` | `/sync-status` | When the last background poll ran and whether it succeeded. **First thing to check when the Gmail card looks stale.** |
| `POST` | `/refresh` | Force a poll now instead of waiting for the 6h timer. |
| `GET` | `/auth/login` | Starts the Google OAuth consent flow. Visit in a browser. |
| `GET` | `/auth/callback?code=&error=` | OAuth redirect target. Set as `GOOGLE_REDIRECT_URI`. |
| `GET` | `/internal/token` | **Internal.** Hands the current Google access token to the `schedule` service so it can write to Calendar. Not intended for the browser — but note it *is* reachable through the gateway as `/api/gmail/internal/token`, which is only acceptable because the LAN is the trust boundary. |
| `GET` | `/sample` | Sample payload for development without a connected account. |

**The OAuth scope trap.** The scope set includes `calendar.events`, added so
`schedule` could write real calendar entries. A refresh token minted before
that addition carries only `gmail.modify` and **403s on every Calendar call**.
Symptom: Gmail works, calendar silently stops updating. Fix: visit
`/auth/login` once and re-consent.

## schedule — `:8084` — calendar

Persists events in Postgres and mirrors them into the **real Google Calendar**,
using a token borrowed from the `gmail` service.

| Method | Path | Description |
|---|---|---|
| `GET` | `/events?include_declined=false` | List events. Declined slots are hidden by default; `include_declined=true` returns them (they are kept as an audit trail, never deleted from Postgres). |
| `POST` | `/events` | Create an event. Idempotent on the thread/slot identity, so re-running a sync does not duplicate. |
| `PATCH` | `/events/{event_id}/status` | Move one event between pending / confirmed / declined. |
| `POST` | `/events/resolve-thread` | **The pipeline's decision endpoint.** Applies a thread-level outcome: confirming one slot auto-declines and removes every other proposed slot on that thread; a counter updates the pending slots to the new offer; a decline clears them all. |
| `POST` | `/sync-from-calendar` | Pull changes made directly in Google Calendar back into the local store. |

Color coding is pushed to Google Calendar so pending vs. confirmed is visible
in both places: 🟡 proposed by you, 🟠 they countered, 🟢 confirmed. Declining
**removes** the event from Google Calendar but keeps the Postgres row marked
`declined`.

## firefly — `:8097` — read-only Firefly III client

Surfaces the self-hosted Firefly III instance. Empty `FIREFLY_TOKEN` = sample
data. The token never reaches the browser.

| Method | Path | Description |
|---|---|---|
| `GET` | `/summary` | Card-level rollup. |
| `GET` | `/dashboard` | The full dashboard payload — net worth, month spend/income, accounts, recent transactions. |
| `GET` | `/spending` | Spending breakdown, including the 30-day category pie. |
| `GET` | `/month` | This month's figures. |
| `GET` | `/bills` | Bills known to Firefly. |
| `GET` | `/networth` | Net worth: every asset and liability account with its `kind` and `role`. Feeds the runway and the Settings account picker. |
| `GET` | `/audit` | Diagnostic view for reconciling the numbers. |

All date windows are computed in `LOCAL_TZ` and are guarded against
zero-length ranges — Firefly returns **422** for a range where start equals
end, which is what broke the money section on 2026-09-01. See
[TESTING.md](TESTING.md).

## budget — `:8088` — time-aware budgets

Stateless. Budget definitions live in `core`'s settings; transactions come from
the `firefly` service.

| Method | Path | Description |
|---|---|---|
| `GET` | `/status?fresh=0` | Per-category budget status — spent, remaining, over. `fresh=1` bypasses the cache and re-reads Firefly. |
| `GET` | `/summary` | Card-level rollup. |

"Time-aware" means the elapsed fraction of the period is part of the judgment:
being 50% through a budget on day 3 is not the same as on day 25. The honesty
rules in [BUDGETS.md](BUDGETS.md) apply here — **zero and unknown are different
states, suppressed values are `null` and never `0`, and a partial window is
never presented as complete.**

## weather — conditions for a place you pick

Open-Meteo, which needs no API key — the same reason `stocks` uses Stooq. A
feature that stops working when a free tier lapses breaks silently six months
later on a dashboard nobody is auditing.

**Stateless.** No database, no volume. The chosen location lives in `core`
settings under `weather` (`place`, `lat`, `lon`, `timezone`, `unit`), beside
`market.holdings`, so it survives a rebuild of this container.

**Three states.** `not_configured` (no location chosen), `unreachable` (we
asked and got nothing) and `ok` are different answers and `/current` says
which. A temperature is `null` unless the upstream sent it: this is the one
card read without being read, and 0° from a timed-out request is believable in
February.

| Method | Path | Description |
|---|---|---|
| `GET` | `/current` | Now, the next 12 hours, and the next 10 days, with per-day bar geometry. Carries `unit` and `degree` so no reader assumes a scale. |
| `GET` | `/search?q=` | Place lookup for the location picker. Returns `[]` for "no such town" and `state: "unreachable"` for a failed search — Open-Meteo omits its `results` key entirely when nothing matches, so those two arrive looking alike. |
| `GET` | `/health` | Whether a location is configured, and whether anything is cached. |

Times come back from Open-Meteo as naive local wall clock, so the forecast is
timed in the **location's** timezone, not the box's. Asking "what time is it in
Denver" from a machine in New York is why `_now()` takes a zone name.

## amex — statement credits

Tracks the Amex Platinum and Gold statement credits, which reset on a CALENDAR
boundary (monthly, quarterly from 1 Jan, semi-annual from 1 Jan/1 Jul, or
annual) and do NOT roll over. The catalogue lives in
`services/amex/app/credits.py` as editable data, because these are terms Amex
changes rather than facts about the world — every response carries
`catalogue_checked`, the date a human last reconciled it, so a stale list
announces itself instead of being quietly believed.

Several credits require **enrollment**; an unenrolled credit pays nothing and
looks identical to one you simply did not use, so rows carry `enroll`.

| Method | Path | Description |
|---|---|---|
| `GET` | `/summary?card=` | Every credit's state today, soonest expiry first, plus `at_risk` (unused and dying within 7 days), `available`, and a year-to-date block against the annual fees. |
| `POST` | `/used` | Mark a credit used — or not — for the period it is in *right now*. Idempotent on `(credit, period)`. |
| `GET` | `/health` | Row count and `catalogue_checked`. |

`amount` on `POST /used` is optional and means what you actually drew: a $25
credit you only spent $9 of returned $9, and `0` means used-but-nothing, which
is not the same as omitting it. Marking a credit used says something about that
period alone — September's Dunkin' credit says nothing about October's.

## stocks — `:8099` — portfolio & watchlist

Keyless quotes via Stooq, with Yahoo as the fallback. Holdings live in `core`
settings, per account, with each account's cash:

```
market.accounts   = [{name, holdings: [{symbol, shares, cost?}], cash}]
market.recurring  = [{account, cadence_days, next: "YYYY-MM-DD", buys: {SYMBOL: dollars}}]
```

Accounts at one broker share a first word ("Fidelity Roth", "Fidelity
Individual") and the home card shows them as one total with the split beneath.
A pre-2026-10-07 settings row carrying only `market.holdings` is read as one
account named Robinhood.

A recurring plan is money that lands on a schedule. On and after `next`, a
`/portfolio` read turns each buy into shares at that day's quote, saves them
back to `core`, and advances `next` by `cadence_days` (every missed period is
applied). Those shares are **estimates** — the broker filled at its own price —
so the holding carries `estimated_shares` / `estimated_since` and the card says
*est.* until the count is replaced from the statement. A basket with any
unpriced symbol is deferred, never guessed.

| Method | Path | Description |
|---|---|---|
| `GET` | `/quotes?symbols=A,B` | Raw quotes. |
| `GET` | `/portfolio` | `value` (every account incl. cash), `day_change`, `total_gain`, `accounts[]` (each valued, with its cash, gain and estimated lots), `positions[]` combined by symbol across accounts, `movers`, `watchlist`, `next_contribution`, `applied_contributions` (this read), `contribution_save_failed`. |

## Error conventions

| Status | Meaning |
|---|---|
| `404` | Unknown app key at the gateway. |
| `422` | FastAPI request-validation failure (also what Firefly III returns for a zero-length date range). |
| `502` | The gateway reached the proxy layer but the upstream sub-app was unreachable. |

Read endpoints are designed to **degrade rather than fail**: a service that
cannot reach its upstream generally returns a payload marked not-connected or
with `null` values rather than raising. The one rule that governs this, in the
money layer, is that `null` means unknown and `0` means genuinely zero — they
are never interchanged.
